Git — onde fazer commit (não acumules tudo num só)

Todos · regra obrigatória

Faz 1 commit (ou PR) por fase concluída e testada. Nunca commits gigantes com backend + frontend + docs misturados.

Workflow diário (copiar/colar)
git checkout develop
git pull origin develop
git checkout -b NOME_DA_BRANCH    # ver tabela abaixo
# ... trabalhar só nos ficheiros dessa fase ...
git add PASTAS_DA_FASE            # ver tabela — NÃO uses "git add ." cegamente
git commit -m "tipo(escopo): mensagem"
git push -u origin NOME_DA_BRANCH
# Abrir Pull Request no GitHub → develop → squash merge

Setup inicial

Todos · ~2–4h

Preparar as duas máquinas-base: a solução .NET e o projeto Angular. Sem isto, nada compila.

Backend — preencher por esta ordem
  1. backend/NzolaNet.sln + os 4 *.csproj (criar a solução e referências entre projetos)
  2. backend/NzolaNet.Api/appsettings.json — connection string do SQL Server + chave/issuer/audience do JWT
  3. backend/NzolaNet.Api/Properties/launchSettings.json — porta (ex.: 5000)
# criar solução e projetos (a partir de backend/)
dotnet new sln -n NzolaNet
dotnet new webapi   -n NzolaNet.Api
dotnet new classlib -n NzolaNet.Application
dotnet new classlib -n NzolaNet.Domain
dotnet new classlib -n NzolaNet.Infrastructure
# referências: Api→Application, Application→Domain, Infrastructure→Application+Domain
# NuGet no Api/Infrastructure: EFCore.SqlServer, EFCore.Tools, JwtBearer, BCrypt.Net-Next, AutoMapper, FluentValidation, Swashbuckle
Frontend — inicializar
# num diretório temporário e depois copiar p/ frontend/ (mantendo o src/app já criado)
ng new nzolanet --style=scss --routing=true
# instalar: TailwindCSS ou Bootstrap, ngx-toastr, date-fns, jwt-decode
✅ Como testar
  • Backend: dotnet build compila sem erros.
  • Frontend: ng serve abre a app em branco em http://localhost:4200.
🛑 COMMIT #0 — após teste OK
git checkout develop && git pull origin develop
git checkout -b chore/setup
git add backend/NzolaNet.sln backend/NzolaNet.*/NzolaNet.*.csproj
git add backend/NzolaNet.Api/appsettings.json backend/NzolaNet.Api/Properties/
git add frontend/package.json frontend/angular.json frontend/tsconfig*.json
git commit -m "chore(setup): inicializa solucao .NET e projeto Angular"
git push -u origin chore/setup

Backend · Infraestrutura + Base de Dados

Backend · ~4–5h

Ligar ao SQL Server com EF Core, criar as tabelas (migration) e implementar os repositórios e serviços técnicos.

Preencher por esta ordem
  1. Infrastructure/Data/ApplicationDbContext.cs (DbSets)
  2. Infrastructure/Data/Configurations/*Configuration.cs (Fluent API: chaves, índices, UNIQUE, CHECK)
  3. Infrastructure/Services/PasswordHasher.cs (BCrypt)
  4. Infrastructure/Services/JwtTokenService.cs
  5. Infrastructure/Services/LocalFileStorageService.cs (upload)
  6. Infrastructure/Services/EmailService.cs (recuperação de senha — pode ser simulado/log)
  7. Infrastructure/Repositories/*Repository.cs (todas as implementações)
  8. Infrastructure/Data/Seed/DbSeeder.cs (utilizador admin + dados de exemplo)
# gerar e aplicar a migration (a partir do projeto Api)
dotnet ef migrations add InitialCreate -p ../NzolaNet.Infrastructure -s .
dotnet ef database update -p ../NzolaNet.Infrastructure -s .
✅ Como testar
  • No SSMS, a base NzolaNetDB existe com as tabelas Users, Posts, Comments, Follows, PasswordResetTokens.
  • O seed criou pelo menos 1 utilizador.

Backend · Aplicação (regras de negócio)

Backend · ~5–6h

DTOs, mapeamentos, validações e a lógica de negócio nos Services. Aqui está o "cérebro" da API.

Preencher por esta ordem
  1. Application/DTOs/Common/ (PagedResultDto, MessageDto)
  2. Application/DTOs/Auth/ → Users/ → Posts/ → Comments/
  3. Application/Exceptions/ (NotFound, Forbidden, BadRequest, Conflict)
  4. Application/Mappings/AutoMapperProfile.cs
  5. Application/Interfaces/ (todas as I*Service)
  6. Application/Validators/ (Register, CreatePost, CreateComment)
  7. Application/Services/AuthService.cs → UserService → FollowService → PostService → CommentService
Regras críticas (não esquecer): editar/apagar só pelo autor; não seguir-se a si próprio; password com BCrypt; nunca devolver entidades — sempre DTOs.
✅ Como testar

Backend · API (Controllers) — primeira coisa testável a sério

Backend · ~3–4h

Expor a API por HTTP, configurar JWT/CORS/Swagger e os controllers. No fim desta fase tens uma API funcional.

Preencher por esta ordem
  1. Api/Program.cs (DI dos repos/services, JWT, CORS p/ localhost:4200, Swagger, UseStaticFiles)
  2. Api/Middleware/ExceptionHandlingMiddleware.cs (mapear exceções → códigos HTTP)
  3. Api/Controllers/AuthController.cs
  4. Api/Controllers/UsersController.cs
  5. Api/Controllers/PostsController.cs
  6. Api/Controllers/CommentsController.cs
dotnet run --project NzolaNet.Api   # abrir https://localhost:xxxx/swagger
✅ Como testar (no Swagger)
  • POST /auth/register cria utilizador → POST /auth/login devolve token JWT.
  • "Authorize" no Swagger com o token → POST /posts (com imagem) cria publicação.
  • GET /posts lista em ordem cronológica; PUT/DELETE só funciona no próprio.
  • POST /posts/{id}/comments e editar/apagar comentário próprio.
  • POST /users/{id}/follow segue; impede seguir-se a si próprio.
Marco 1: backend 100% testável via Swagger. Atualiza agora docs/API_CONTRACT.md com o que ficou estável — os FE-Devs dependem disto.

Integração ponta-a-ponta (todos)

Equipa · ~4–6h

Juntar tudo, caçar bugs e garantir os requisitos não-funcionais.

✅ Checklist de teste end-to-end
  • Fluxo completo: registar → login → editar perfil + foto → criar post com imagem → editar post → comentar → editar/apagar comentário → seguir outro user.
  • Segurança: sem token, endpoints privados devolvem 401; editar conteúdo de outro devolve 403.
  • Responsividade: testar em 320px (telemóvel), 768px (tablet), 1024px (desktop).
  • Feedback: spinners durante chamadas, toasts em sucesso/erro.
  • Validações client-side: email válido, password mín. 8 caracteres, campos obrigatórios.
