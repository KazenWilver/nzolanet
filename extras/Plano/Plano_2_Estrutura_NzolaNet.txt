# NzolaNet — Estrutura Completa do Sistema
> Stack: Angular · ASP.NET Web API · SQL Server  
> Arquitetura: Camadas (Repository → Service → Controller) + DTOs  
> Objetivo: 20/20

---

## 0. Análise do Enunciado

### Domínios do Sistema
| Domínio | Funcionalidades-chave |
|---|---|
| Utilizadores | Registo, login, recuperação de senha, editar perfil, foto de perfil, seguir/deixar de seguir |
| Publicações | CRUD próprio, texto + imagem (opcional) + vídeo (opcional), visualização cronológica |
| Bazes | Dar/remover (toggle), contador, unicidade por utilizador por publicação |
| Comentários | CRUD próprio, lista por publicação |
| Feed | Posts recentes + posts de seguidos, cronológico, atualização dinâmica |
| Notificações | Baze recebido, comentário recebido, novo seguidor |

### Regras de Negócio Extraídas
1. Apenas utilizadores autenticados podem publicar, comentar ou dar baze.
2. Utilizador só edita/exclui conteúdo da sua própria autoria.
3. Máximo 1 baze por utilizador por publicação (toggle on/off).
4. Administrador pode remover qualquer comentário ofensivo.
5. Perfil pode ser Público ou Privado.
6. Notificações automáticas: baze, comentário e novo seguidor.

### Requisitos Não Funcionais Relevantes para Decisões Técnicas
- Interface responsiva → Angular com layout flexível/grid
- Segurança na autenticação → JWT Bearer
- Proteção contra acessos não autorizados → Guards (Angular) + [Authorize] (API)
- Boa performance → paginação no feed, lazy loading de módulos Angular
- Usabilidade intuitiva → componentes reutilizáveis, feedback visual imediato

## BASE DE DADOS — SQL Server

### Modelo Relacional (Normalizado — 3FN)

```
Users (Id, Username, Email, PasswordHash, FullName, Bio, ProfilePhotoUrl,
       IsPrivate, Role, CreatedAt, UpdatedAt)

Publications (Id, UserId FK, Content, ImageUrl, VideoUrl, CreatedAt, UpdatedAt)

Bazes (Id, UserId FK, PublicationId FK, CreatedAt)
      UNIQUE CONSTRAINT (UserId, PublicationId)

Comments (Id, UserId FK, PublicationId FK, Content, CreatedAt, UpdatedAt)

Follows (Id, FollowerId FK → Users, FollowedId FK → Users, CreatedAt)
        UNIQUE CONSTRAINT (FollowerId, FollowedId)

Notifications (Id, RecipientId FK → Users, SenderId FK → Users,
               Type [Baze|Comment|Follow], PublicationId FK nullable,
               IsRead, CreatedAt)
```

### Relacionamentos
```
Users         1 ─── N   Publications
Users         1 ─── N   Comments
Users         1 ─── N   Bazes
Users (Follower)  N ─── N   Users (Followed)  →  tabela Follows
Publications  1 ─── N   Comments
Publications  1 ─── N   Bazes
Publications  1 ─── N   Notifications (nullable)
Users         1 ─── N   Notifications (recipient)
Users         1 ─── N   Notifications (sender)
```

### Script SQL — Criação das Tabelas
```sql
CREATE TABLE Users (
    Id          INT IDENTITY PRIMARY KEY,
    Username    NVARCHAR(50)  NOT NULL UNIQUE,
    Email       NVARCHAR(100) NOT NULL UNIQUE,
    PasswordHash NVARCHAR(255) NOT NULL,
    FullName    NVARCHAR(100) NOT NULL,
    Bio         NVARCHAR(300) NULL,
    ProfilePhotoUrl NVARCHAR(500) NULL,
    IsPrivate   BIT NOT NULL DEFAULT 0,
    Role        NVARCHAR(20)  NOT NULL DEFAULT 'User', -- 'User' | 'Admin'
    CreatedAt   DATETIME2 NOT NULL DEFAULT GETUTCDATE(),
    UpdatedAt   DATETIME2 NOT NULL DEFAULT GETUTCDATE()
);

CREATE TABLE Publications (
    Id        INT IDENTITY PRIMARY KEY,
    UserId    INT NOT NULL REFERENCES Users(Id) ON DELETE CASCADE,
    Content   NVARCHAR(2000) NOT NULL,
    ImageUrl  NVARCHAR(500) NULL,
    VideoUrl  NVARCHAR(500) NULL,
    CreatedAt DATETIME2 NOT NULL DEFAULT GETUTCDATE(),
    UpdatedAt DATETIME2 NOT NULL DEFAULT GETUTCDATE()
);

CREATE TABLE Bazes (
    Id            INT IDENTITY PRIMARY KEY,
    UserId        INT NOT NULL REFERENCES Users(Id) ON DELETE NO ACTION,
    PublicationId INT NOT NULL REFERENCES Publications(Id) ON DELETE CASCADE,
    CreatedAt     DATETIME2 NOT NULL DEFAULT GETUTCDATE(),
    CONSTRAINT UQ_Baze UNIQUE (UserId, PublicationId)
);

CREATE TABLE Comments (
    Id            INT IDENTITY PRIMARY KEY,
    UserId        INT NOT NULL REFERENCES Users(Id) ON DELETE NO ACTION,
    PublicationId INT NOT NULL REFERENCES Publications(Id) ON DELETE CASCADE,
    Content       NVARCHAR(1000) NOT NULL,
    CreatedAt     DATETIME2 NOT NULL DEFAULT GETUTCDATE(),
    UpdatedAt     DATETIME2 NOT NULL DEFAULT GETUTCDATE()
);

CREATE TABLE Follows (
    Id         INT IDENTITY PRIMARY KEY,
    FollowerId INT NOT NULL REFERENCES Users(Id),
    FollowedId INT NOT NULL REFERENCES Users(Id),
    CreatedAt  DATETIME2 NOT NULL DEFAULT GETUTCDATE(),
    CONSTRAINT UQ_Follow UNIQUE (FollowerId, FollowedId),
    CONSTRAINT CHK_NoSelfFollow CHECK (FollowerId <> FollowedId)
);

CREATE TABLE Notifications (
    Id              INT IDENTITY PRIMARY KEY,
    RecipientId     INT NOT NULL REFERENCES Users(Id) ON DELETE NO ACTION,
    SenderId        INT NOT NULL REFERENCES Users(Id) ON DELETE NO ACTION,
    Type            NVARCHAR(20) NOT NULL, -- 'Baze' | 'Comment' | 'Follow'
    PublicationId   INT NULL REFERENCES Publications(Id) ON DELETE SET NULL,
    IsRead          BIT NOT NULL DEFAULT 0,
    CreatedAt       DATETIME2 NOT NULL DEFAULT GETUTCDATE()
);
```

```typescript
@Injectable({ providedIn: 'root' })
export class AuthService {
  private apiUrl = environment.apiUrl;

  login(data: LoginRequest): Observable<AuthResponse> { ... }
  register(data: RegisterRequest): Observable<AuthResponse> { ... }

  logout(): void { localStorage.removeItem('token'); this.currentUser$.next(null); }
```

## Interceptor JWT

```typescript
// core/interceptors/auth.interceptor.ts
export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const token = inject(AuthService).getToken();
  if (token) {
    req = req.clone({ setHeaders: { Authorization: `Bearer ${token}` } });
  }
  return next(req);
};
```

```csharp
public class User {

    public string Role { get; set; } = "User"; // "User" | "Admin"
    public DateTime CreatedAt { get; set; } = DateTime.UtcNow;
    public DateTime UpdatedAt { get; set; } = DateTime.UtcNow;

    public ICollection<Publication> Publications { get; set; } = [];
    public ICollection<Baze> Bazes { get; set; } = [];
    public ICollection<Comment> Comments { get; set; } = [];
    public ICollection<Follow> Followers { get; set; } = [];
    public ICollection<Follow> Following { get; set; } = [];
    public ICollection<Notification> NotificationsReceived { get; set; } = [];
    public ICollection<Notification> NotificationsSent { get; set; } = [];
}

// Models/Publication.cs
public class Publication {
    public int Id { get; set; }
    public int UserId { get; set; }
    public User User { get; set; } = null!;
    public string Content { get; set; } = string.Empty;
```

```csharp
// Data/AppDbContext.cs
public class AppDbContext(DbContextOptions<AppDbContext> options) : DbContext(options)
{
    public DbSet<User> Users => Set<User>();
    public DbSet<Publication> Publications => Set<Publication>();
    public DbSet<Baze> Bazes => Set<Baze>();
    public DbSet<Comment> Comments => Set<Comment>();
    public DbSet<Follow> Follows => Set<Follow>();
    public DbSet<Notification> Notifications => Set<Notification>();

    protected override void OnModelCreating(ModelBuilder mb)
    {
        // Unicidade: 1 baze por utilizador por publicação
        mb.Entity<Baze>()
          .HasIndex(b => new { b.UserId, b.PublicationId }).IsUnique();

        // Unicidade: seguir uma vez
        mb.Entity<Follow>()
          .HasIndex(f => new { f.FollowerId, f.FollowedId }).IsUnique();

        // Relações de Follow (auto-referência)
        mb.Entity<Follow>()
          .HasOne(f => f.Follower).WithMany(u => u.Following)
          .HasForeignKey(f => f.FollowerId).OnDelete(DeleteBehavior.NoAction);

        mb.Entity<Follow>()
          .HasOne(f => f.Followed).WithMany(u => u.Followers)
          .HasForeignKey(f => f.FollowedId).OnDelete(DeleteBehavior.NoAction);

        // Notificações (evitar múltiplas cascatas)
        mb.Entity<Notification>()
          .HasOne(n => n.Recipient).WithMany(u => u.NotificationsReceived)
          .HasForeignKey(n => n.RecipientId).OnDelete(DeleteBehavior.NoAction);

        mb.Entity<Notification>()
          .HasOne(n => n.Sender).WithMany(u => u.NotificationsSent)
          .HasForeignKey(n => n.SenderId).OnDelete(DeleteBehavior.NoAction);
    }
}
```

```csharp
// Services/BazeService.cs
public async Task<BazeToggleResultDto> ToggleBazeAsync(int userId, int publicationId)
{
    var existing = await _bazeRepo.GetAsync(userId, publicationId);
    if (existing is not null)
    {
        await _bazeRepo.RemoveAsync(existing);
    }
    else
    {
        await _bazeRepo.AddAsync(new Baze { UserId = userId, PublicationId = publicationId });

        // Notificar dono da publicação (se não for o próprio)
        var publication = await _publicationRepo.GetByIdAsync(publicationId);
        if (publication!.UserId != userId)
            await _notificationService.CreateAsync(publication.UserId, userId, "Baze", publicationId);
    }

    var count = await _bazeRepo.CountByPublicationAsync(publicationId);
    return new BazeToggleResultDto(count, existing is null);
}
```

## Lógica de Feed

```csharp
// Repositories/PublicationRepository.cs
public async Task<IEnumerable<Publication>> GetFeedAsync(int userId, int page, int pageSize)
{
    var followedIds = await _context.Follows
        .Where(f => f.FollowerId == userId)
        .Select(f => f.FollowedId)
        .ToListAsync();

    return await _context.Publications
        .Include(p => p.User)
        .Include(p => p.Bazes)
        .Include(p => p.Comments)
        .Where(p => followedIds.Contains(p.UserId) || p.UserId == userId)
        .OrderByDescending(p => p.CreatedAt)
        .Skip((page - 1) * pageSize)
        .Take(pageSize)
        .ToListAsync();
}
```

## Regras de Trabalho

### 1. Setup inicial (feito 1 vez pelo líder do grupo)
```bash
git clone https://github.com/grupo/nzolanet.git
git checkout -b develop
git push origin develop
# Definir develop como branch padrão no GitHub Settings
```

### 2. Cada dev começa assim
```bash
git checkout develop
git pull origin develop
git checkout -b feature/fe-auth    # substitui pelo teu branch
```

### 3. Commitar regularmente (pelo menos 1x por sessão de trabalho)
```bash
git add .
git commit -m "feat(auth): implementa login e registo com JWT"
git push origin feature/fe-auth
```

### 4. Convenção de commits (para clareza)
```
feat(módulo): descrição curta do que foi adicionado
fix(módulo): descrição do bug corrigido
refactor(módulo): melhoria sem mudar comportamento
chore: tarefas de manutenção (configs, packages)

Exemplos:
feat(backend/publications): CRUD de publicações com upload de media
feat(fe-feed): componente publication-card com toggle de baze
fix(backend/bazes): corrige constraint de unicidade no toggle
```

### 5. Pull Request (PR) → develop
```
- Quando a feature estiver funcional, abre um PR no GitHub
- Título: [FEAT] Gestão de Publicações — Backend
- Descrição: lista o que foi implementado
- Assign: o outro membro revê (pelo menos 1 aprovação)
- Merge: Squash and merge (mantém o histórico limpo)
```

### 6. Merge de develop → main
```bash
# Só quando uma fase estiver completa (ex: 2ª parcelar)
git checkout main
git merge develop --no-ff -m "release: 2ª parcelar — Users, Publications, Comments"
git push origin main
git tag v1.0-parcelar2
git push origin --tags
```

## Como Evitar Conflitos

| Risco | Prevenção |
|---|---|
| Dois devs editam o mesmo ficheiro | Divisão clara de responsabilidades por módulo/pasta |
| Divergência entre branches | `git pull origin develop` **antes** de começar a trabalhar cada dia |
| Conflitos no `app.module.ts` | Só quem está a criar um módulo novo toca no `app.module.ts`; abre PR imediatamente |
| Conflitos no `app-routing.module.ts` | Idem — definir as rotas em conjunto no início e só alterar via PR |
| Backend e frontend fora de sincronia | Manter um ficheiro `API_CONTRACT.md` com os endpoints acordados, actualizado em conjunto |
