# Análise e Estruturação do Sistema NzolaNet

## 1. Análise de Requisitos (Base: Enunciado AW.pdf)

### 1.1 Requisitos Funcionais Mapeados
| Módulo | Funcionalidade | Regra de Negócio Crítica |
|--------|---------------|-------------------------|
| **Utilizadores** | Registo, Login, Recuperação, Edição, Follow | Apenas utilizadores autenticados publicam; perfis privados visíveis só a seguidores |
| **Publicações** | CRUD, Upload Mídia, Visualização Cronológica | Edição/exclusão apenas pelo autor; mídia opcional (imagem OU vídeo) |
| **Bazes** | Like/Unlike, Contagem | **UNIQUE constraint**: 1 utilizador = 1 baze por publicação |
| **Comentários** | CRUD por publicação | Admin remove qualquer comentário; utilizador só edita/exclui os seus |
| **Feed** | Posts recentes + seguidos, ordenação cronológica | Atualização dinâmica; filtragem por privacidade do autor |
| **Notificações** | Trigger: Baze, Comentário, Novo Seguidor | Apenas para ações de terceiros; não notificar auto-ações |

### 1.2 Requisitos Não-Funcionais
- **Segurança**: JWT Auth, proteção contra acesso não autorizado, sanitização de inputs.
- **Performance**: Carregamento eficiente (paginação, lazy loading), queries otimizadas.
- **UX/UI**: Responsivo (mobile-first), intuitivo, feedback visual imediato.

### 1.3 Stack Tecnológico Confirmado
- **Frontend**: Angular (v17+)
- **Backend**: ASP.NET Web API (.NET 8)
- **Database**: SQL Server
- **Arquitetura**: Layered (Controllers → Services → Repositories) + DTOs
- **Versionamento**: Git/GitHub

## 2. Modelação de Dados (SQL Server - 3NF)

```sql
-- Tabela: Users
CREATE TABLE Users (
    Id UNIQUEIDENTIFIER PRIMARY KEY DEFAULT NEWID(),
    Username NVARCHAR(50) UNIQUE NOT NULL,
    Email NVARCHAR(100) UNIQUE NOT NULL,
    PasswordHash NVARCHAR(255) NOT NULL,
    FullName NVARCHAR(100),
    Bio NVARCHAR(500),
    ProfilePhotoUrl NVARCHAR(255),
    IsPrivate BIT DEFAULT 0,
    IsAdmin BIT DEFAULT 0,
    CreatedAt DATETIME2 DEFAULT GETUTCDATE(),
    UpdatedAt DATETIME2,
    LastLoginAt DATETIME2
);
CREATE INDEX IX_Users_Username ON Users(Username);

-- Tabela: Posts
CREATE TABLE Posts (
    Id UNIQUEIDENTIFIER PRIMARY KEY DEFAULT NEWID(),
    UserId UNIQUEIDENTIFIER FOREIGN KEY REFERENCES Users(Id) ON DELETE CASCADE NOT NULL,
    TextContent NVARCHAR(MAX) NOT NULL,
    ImageUrl NVARCHAR(255),
    VideoUrl NVARCHAR(255),
    CreatedAt DATETIME2 DEFAULT GETUTCDATE(),
    UpdatedAt DATETIME2,
    IsDeleted BIT DEFAULT 0
);
CREATE INDEX IX_Posts_UserId_CreatedAt ON Posts(UserId, CreatedAt DESC);

-- Tabela: Likes (Bazes) - Prevenção de duplicados via constraint
CREATE TABLE Likes (
    Id UNIQUEIDENTIFIER PRIMARY KEY DEFAULT NEWID(),
    PostId UNIQUEIDENTIFIER FOREIGN KEY REFERENCES Posts(Id) ON DELETE CASCADE NOT NULL,
    UserId UNIQUEIDENTIFIER FOREIGN KEY REFERENCES Users(Id) ON DELETE CASCADE NOT NULL,
    CreatedAt DATETIME2 DEFAULT GETUTCDATE(),
    CONSTRAINT UQ_Likes_Post_User UNIQUE(PostId, UserId)
);

-- Tabela: Comments
CREATE TABLE Comments (
    Id UNIQUEIDENTIFIER PRIMARY KEY DEFAULT NEWID(),
    PostId UNIQUEIDENTIFIER FOREIGN KEY REFERENCES Posts(Id) ON DELETE CASCADE NOT NULL,
    UserId UNIQUEIDENTIFIER FOREIGN KEY REFERENCES Users(Id) ON DELETE CASCADE NOT NULL,
    TextContent NVARCHAR(1000) NOT NULL,
    CreatedAt DATETIME2 DEFAULT GETUTCDATE(),
    UpdatedAt DATETIME2,
    IsDeleted BIT DEFAULT 0
);
CREATE INDEX IX_Comments_PostId_CreatedAt ON Comments(PostId, CreatedAt);

-- Tabela: Follows
CREATE TABLE Follows (
    Id UNIQUEIDENTIFIER PRIMARY KEY DEFAULT NEWID(),
    FollowerId UNIQUEIDENTIFIER FOREIGN KEY REFERENCES Users(Id) ON DELETE CASCADE NOT NULL,
    FollowedId UNIQUEIDENTIFIER FOREIGN KEY REFERENCES Users(Id) ON DELETE CASCADE NOT NULL,
    CreatedAt DATETIME2 DEFAULT GETUTCDATE(),
    CONSTRAINT UQ_Follows_Pair UNIQUE(FollowerId, FollowedId),
    CONSTRAINT CK_Follows_NotSelf CHECK (FollowerId != FollowedId)
);

-- Tabela: Notifications
CREATE TABLE Notifications (
    Id UNIQUEIDENTIFIER PRIMARY KEY DEFAULT NEWID(),
    UserId UNIQUEIDENTIFIER FOREIGN KEY REFERENCES Users(Id) ON DELETE CASCADE NOT NULL, -- Recipient
    Type NVARCHAR(50) NOT NULL, -- 'Like', 'Comment', 'Follow'
    SourceUserId UNIQUEIDENTIFIER FOREIGN KEY REFERENCES Users(Id), -- Who triggered
    PostId UNIQUEIDENTIFIER FOREIGN KEY REFERENCES Posts(Id),
    CommentId UNIQUEIDENTIFIER FOREIGN KEY REFERENCES Comments(Id),
    IsRead BIT DEFAULT 0,
    CreatedAt DATETIME2 DEFAULT GETUTCDATE()
);
CREATE INDEX IX_Notifications_UserId_IsRead ON Notifications(UserId, IsRead);

-- Tabela: PasswordResetTokens
CREATE TABLE PasswordResetTokens (
    Id UNIQUEIDENTIFIER PRIMARY KEY DEFAULT NEWID(),
    UserId UNIQUEIDENTIFIER FOREIGN KEY REFERENCES Users(Id) ON DELETE CASCADE NOT NULL,
    Token NVARCHAR(255) UNIQUE NOT NULL,
    ExpiresAt DATETIME2 NOT NULL,
    IsUsed BIT DEFAULT 0,
    CreatedAt DATETIME2 DEFAULT GETUTCDATE()
);
```

### Padrão DTO (Exemplo Crítico)
```csharp
// Request DTO - Validação na entrada
public record CreatePostDto(string TextContent, IFormFile? Image, IFormFile? Video);
// Validator (FluentValidation)
public class CreatePostDtoValidator : AbstractValidator<CreatePostDto> {
    public CreatePostDtoValidator() {
        RuleFor(x => x.TextContent).NotEmpty().MaximumLength(5000);
        RuleFor(x => x.Image).Must(BeValidImage).WithMessage("Apenas JPG, PNG");
        RuleFor(x => x.Video).Must(BeValidVideo).When(x => x.Image != null)
            .WithMessage("Escolha imagem OU vídeo, não ambos");
    }
}

// Response DTO - Segurança na saída (sem dados sensíveis)
public record PostDto(
    Guid Id,
    string AuthorName,
    string? AuthorPhotoUrl,
    DateTime CreatedAt,
    string TextContent,
    string? MediaUrl,
    MediaType? MediaType, // Enum: Image, Video
    int LikesCount,
    int CommentsCount,
    bool IsLikedByCurrentUser // Otimização UI
);
```

### Endpoints Principais (REST)
```
POST   /api/auth/register          # RegisterDto → AuthResponseDto
POST   /api/auth/login             # LoginDto → JWT + UserProfileDto
POST   /api/auth/forgot-password   # ForgotPasswordDto → 202 Accepted

GET    /api/users/{username}       # UserProfileDto (público/privado logic)
PUT    /api/users/profile          # [Authorize] UpdateProfileDto
POST   /api/users/{id}/follow      # [Authorize] Follow/Unfollow

GET    /api/feed                   # [Authorize] PagedResult<FeedPostDto>
POST   /api/posts                  # [Authorize] CreatePostDto → PostDto
PUT    /api/posts/{id}             # [Authorize] Owner-only update
DELETE /api/posts/{id}             # [Authorize] Owner-only delete

POST   /api/posts/{id}/likes       # [Authorize] Like/Unlike (idempotente)
GET    /api/posts/{id}/comments    # PagedResult<CommentDto>
POST   /api/posts/{id}/comments    # [Authorize] CreateCommentDto

GET    /api/notifications          # [Authorize] PagedResult<NotificationDto>
PUT    /api/notifications/{id}/read # [Authorize] Mark as read
```

### Estratégia de Componentes Reutilizáveis
```typescript
// post-card.component.ts - Usado em Feed, Profile, Search
@Component({
  selector: 'app-post-card',
  template: `
    <article class="post-card">
      <app-user-avatar [user]="post.author" />
      <div class="content">
        <p>{{ post.textContent }}</p>
        <app-media-preview *ngIf="post.mediaUrl" [url]="post.mediaUrl" [type]="post.mediaType" />
        <div class="actions">
          <app-like-button 
            [count]="post.likesCount" 
            [isLiked]="post.isLikedByCurrentUser"
            (toggle)="onLikeToggle($event)">
          </app-like-button>
          <button (click)="openComments()">Comentários ({{ post.commentsCount }})</button>
        </div>
      </div>
    </article>
  `
})
export class PostCardComponent {
  @Input() post!: PostDto;
  @Output() likeToggled = new EventEmitter<{postId: Guid, isLiked: boolean}>();
  
  onLikeToggle(isLiked: boolean) {
    // Optimistic update: UI muda imediatamente
    this.post.isLikedByCurrentUser = isLiked;
    this.post.likesCount += isLiked ? 1 : -1;
    this.likeToggled.emit({ postId: this.post.id, isLiked });
    // Service call happens in parent or via service directly
  }
}
```

### Performance & UX
- **Lazy Loading**: `loadChildren: () => import('./features/feed/feed.module').then(m => m.FeedModule)`
- **OnPush Change Detection**: `changeDetection: ChangeDetectionStrategy.OnPush` em componentes presentacionais
- **Virtual Scroll**: `@angular/cdk/scrolling` para listas longas de comentários
- **Debounce**: `valueChanges.pipe(debounceTime(300))` em campos de pesquisa
- **Skeleton Loaders**: Enquanto dados carregam, mostrar placeholders animados

   ```typescript

   export interface PostDto {
     id: string; // GUID como string

     authorPhotoUrl?: string;

     mediaUrl?: string;

   - Usar `ApiService` base com métodos tipados:

     // core/services/api.service.ts
     getFeed(page: number, pageSize: number): Observable<PagedResult<PostDto>> {
       return this.http.get<PagedResult<PostDto>>(`${this.baseUrl}/feed`, { params: { page, pageSize } });

   - `JwtInterceptor` anexa token automaticamente; `ErrorInterceptor` mostra toast e trata 401 (logout).

   - Reactive Forms com validators customizados (ex: password strength).
   - Sincronizar mensagens de erro com as do backend (ex: "Email já registado").

4. **Responsividade**:
   - Mobile-first com CSS Grid/Flexbox.
   - Testar em breakpoints: 320px (mobile), 768px (tablet), 1024px (desktop).

5. **Testing**:
   - Unit tests para services/pipes (Jasmine/Karma).

   // PostService.cs - Exemplo de regra: apenas autor edita
   public async Task<PostDto> UpdatePostAsync(Guid postId, UpdatePostDto dto, Guid currentUserId) {
       var post = await _postRepository.GetByIdAsync(postId) 
           ?? throw new NotFoundException("Post não encontrado");
       
       if (post.UserId != currentUserId)
           throw new UnauthorizedException("Apenas o autor pode editar esta publicação");
       
       // Atualizar campos permitidos
       post.TextContent = dto.TextContent ?? post.TextContent;
       // ... validar e atualizar mídia se fornecida
       
       await _unitOfWork.SaveChangesAsync();
       return _mapper.Map<PostDto>(post);
   }
   ```

4. **Prevenção de Bazes Duplicados**:
   ```csharp
   // LikeService.cs
   public async Task<bool> ToggleLikeAsync(Guid postId, Guid userId) {
       var existing = await _likeRepository.GetByPostAndUserAsync(postId, userId);
       if (existing != null) {
           await _likeRepository.DeleteAsync(existing.Id); // Remove like
           return false;
       }
       await _likeRepository.AddAsync(new Like { PostId = postId, UserId = userId });
       await _notificationService.CreateLikeNotificationAsync(postId, userId);
       return true;
   }
   ```

5. **Feed Otimizado**:
   ```csharp
   // FeedService.cs - Query eficiente com paginação
   public async Task<PagedResult<FeedPostDto>> GetFeedAsync(Guid userId, int page, int pageSize) {
       var followedIds = await _followRepository.GetFollowedUserIdsAsync(userId);
       
       var query = _postRepository.GetAll()
           .Where(p => !p.IsDeleted && 
                      (p.User.IsPrivate == false || followedIds.Contains(p.UserId)))
           .OrderByDescending(p => p.CreatedAt)
           .Select(p => new FeedPostDto { /* projection */ });
       
       return await PagedResult<FeedPostDto>.CreateAsync(query, page, pageSize);
   }
   ```

6. **Upload de Ficheiros**:
   ```csharp
   // FileStorageService.cs
   public async Task<string> SaveFileAsync(IFormFile file, string folder) {
       var allowedExtensions = new[] { ".jpg", ".jpeg", ".png", ".mp4" };
       var ext = Path.GetExtension(file.FileName).ToLowerInvariant();
       if (!allowedExtensions.Contains(ext))
           throw new BusinessException("Tipo de ficheiro não permitido");
       
       var fileName = $"{Guid.NewGuid()}{ext}";
       var path = Path.Combine("wwwroot/uploads", folder, fileName);
       
       using var stream = new FileStream(path, FileMode.Create);
       await file.CopyToAsync(stream);
       
       return $"/uploads/{folder}/{fileName}"; // URL relativa
   }
   ```

### Estratégia de Branches (Git Flow Simplificado)
```
main (protegido) ← develop (integração) ← feature/* (trabalho diário)
```

#### Convenção de Nomes de Branch
| Tipo | Formato | Exemplo |
|------|---------|---------|
| Feature Backend | `backend/feature/{nome}` | `backend/feature/posts-crud` |
| Feature Frontend | `frontend/feature/{nome}` | `frontend/feature/feed-infinite-scroll` |
| Bug Fix | `fix/{scope}-{descricao}` | `fix/auth-jwt-expiry-handling` |
| Hotfix | `hotfix/{urgente}` | `hotfix/security-cors-misconfig` |

### Workflow Diário Passo-a-Passo
1. **Início do dia**:
   ```bash
   git checkout develop
   git pull origin develop --rebase
   ```

2. **Criar branch para tarefa**:
   ```bash
   # Backend (tu)
   git checkout -b backend/feature/notifications-service
   
   # Frontend (colega)
   git checkout -b frontend/feature/notification-badge-component
   ```

3. **Commits frequentes e descritivos**:
   ```bash
   # Usar Conventional Commits
   git commit -m "feat(likes): add idempotent toggle endpoint with duplicate prevention"
   git commit -m "fix(profile): handle null profile photo in avatar component"
   git commit -m "docs(api): update Swagger examples for comments pagination"
   ```

4. **Push e Pull Request**:
   ```bash
   git push -u origin backend/feature/notifications-service
   # Criar PR no GitHub com template:
   ```
   **Título do PR**: `[Backend] Implement NotificationService with event triggers`
   
   **Descrição**:
   ```markdown
   ## O que foi alterado?
   - Serviço para criação de notificações em Like/Comment/Follow
   - Integração com PostService/CommentService/FollowService
   
   ## Como testar?
   1. Dar like num post → verificar tabela Notifications
   2. Comentar → notificação para autor do post
   3. Seguir utilizador → notificação para seguido
   
   ## Contrato API atualizado?
   - [x] Sim, ver `/docs/api-contract.md` seção Notifications
   - [ ] Não, sem alterações externas
   
   ## Checklist
   - [x] Tests added (xUnit)
   - [x] Swagger docs updated
   - [x] No breaking changes to shared DTOs
   ```

5. **Revisão de Código**:
   - Backend revê PRs frontend que tocam em integração API
   - Frontend revê PRs backend que alteram contratos (DTOs, endpoints)
   - Usar GitHub "Request changes" para bloquear merge se necessário

6. **Merge Strategy**:
   - **Squash merge** para `develop` (histórico limpo)
   - Nunca push direto em `develop` ou `main`
   - Resolver conflitos localmente antes de criar PR

| Cenário | Solução |
|---------|---------|
| Backend altera DTO que frontend usa | 1. Atualizar `/docs/api-contract.md` 2. Notificar equipa no PR 3. Frontend atualiza modelos TypeScript antes de merge |
| Dois devs editam mesmo ficheiro | Comunicação no standup; dividir por pastas (`/backend/Services` vs `/frontend/src/app/features`) |
| Conflito em `package.json`/`.csproj` | Definir um "owner" por ficheiro de configuração; merges manuais com revisão |

### Integração Contínua (GitHub Actions - Opcional mas Recomendado)
```yaml
# .github/workflows/ci.yml
name: CI Build

on: [pull_request]

jobs:
  backend:
    runs-on: ubuntu-latest
    defaults: { run: { working-directory: backend } }
    steps:
      - uses: actions/checkout@v3
      - name: Setup .NET
        uses: actions/setup-dotnet@v3
        with: { dotnet-version: '8.0.x' }
      - run: dotnet restore
      - run: dotnet build --no-restore
      - run: dotnet test --no-build --verbosity normal

  frontend:
    runs-on: ubuntu-latest
    defaults: { run: { working-directory: frontend } }
    steps:
      - uses: actions/checkout@v3
      - name: Setup Node
        uses: actions/setup-node@v3
        with: { node-version: '18.x', cache: 'npm', cache-dependency-path: 'frontend/package-lock.json' }
      - run: npm ci
      - run: npm run lint
      - run: npm run build -- --configuration=production
```

### Ferramentas de Colaboração
1. **Swagger UI** (`https://localhost:5001/swagger`): Documentação viva da API para frontend testar endpoints.
2. **Postman Collection**: Exportar de Swagger → Commit em `/docs/postman/nzolanet-api.postman_collection.json`.
3. **ER Diagram**: Manter atualizado em `/docs/database/erd.png` (usar dbdiagram.io ou SSMS).
4. **API Contract**: Ficheiro markdown em `/docs/api-contract.md` com:
   ```markdown
   ## POST /api/posts
   **Request**: CreatePostDto
   ```json
   { "textContent": "string", "image": "file (optional)", "video": "file (optional)" }
   ```
   **Response**: 201 Created → PostDto
   **Errors**: 400 (Validation), 401 (Unauthorized), 413 (File too large)
   ```
